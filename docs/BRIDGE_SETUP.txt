The bridge receives HIL_ACTUATOR_CONTROLS from PX4, converts each normalized
motor command into rotor speed, and applies quadratic thrust and yaw torque
through PhysX. It sends actual simulated IMU, magnetometer, barometer and GPS
feedback to PX4. PX4 runs the external simulator target rather than SIH physics.

First setup in Isaac
-------------------
1. Stop the timeline and open your drone scene.
2. Keep /World/quadcopter/chassis as a dynamic Rigid Body. Kinematic Enabled
   must be off. Keep gravity on. The scene must use metres, kilograms, Z-up.
3. Under /World/quadcopter/joints, set the lower and upper angular limits to 0
   on rotor_arm0, rotor_arm1, rotor_arm2 and rotor_arm3. These are the folding
   arm hinges, NOT the propeller rotor0..3 joints. Ensure no joint anchors the
   drone to the world. Start the drone level, just above a collidable floor.
4. Disable any controller/graph/script that writes the drone body's pose,
   velocity or motor forces. Sensor ROS publishers may stay enabled.
5. /PhysicsScene must have downward Earth gravity. Direction (0,0,-1) or USD's
   default (0,0,0) both mean downward in a Z-up scene. A negative/default
   gravity magnitude means Earth gravity; explicit 9.80665 is also supported.
   This initial NumPy bridge sets CPU PhysX/MBP and physics to 250 Hz when loaded.

Launch order
------------
1. Close the old PX4 - SITL (SIH) instance. If it is running, enter shutdown at
   its pxh> prompt. Run only one PX4 instance.
2. Open PX4 - XRCE DDS Agent once. The existing Windows v2.4.3 agent uses port
   8888. An already running agent does not need another copy.
   To stop an old agent instance, use PX4 - Stop XRCE DDS Agent on the desktop;
   then open PX4 - XRCE DDS Agent again. The stop shortcut targets only the
   installed PX4 agent executable; it does not stop PX4 or Isaac.
3. Open the NEW desktop shortcut PX4 - Isaac SITL. It waits for Isaac on WSL
   UDP port 14560. Its window remains open on errors.
4. In Isaac, open Window > Script Editor, with the timeline still stopped.
   Execute these two lines:

   import runpy
   runpy.run_path("C:/Users/finel/Documents/ChatGPT/issaac/load_bridge.py")

5. Press Play. Wait for [PX4 bridge] ... fresh=True ... in the Isaac console
   and for PX4 to finish startup. Allow at least 15 simulated seconds for the
   EKF/GPS checks to settle. Motors should be zero while disarmed.
   Each Script Editor execution prints [PX4 bridge loader] Fresh source loaded
   and the raw/effective gravity directions. The loader compiles the project
   files directly to bypass Kit's persistent import-code cache.
6. Keep the drone disarmed for the initial read-only state check described in
   docs/history/FLIGHT_NEXT.txt. The operator requests arming/takeoff and mode selection
   with the dashboard's explicit Flight setup buttons or the PX4 console.
   The upstream px4_ros_com offboard_control example automatically arms and
   commands a 5 m climb; it is not the next step for this room experiment.

This publisher captures current local X/Y and heading, then publishes a position
target at 10 Hz with NED Z = -height. Height is relative to PX4's local origin.
It never arms or changes flight mode. It pauses targets if position is invalid
or no advancing position message has arrived for one wall-clock second.
Outgoing commands request PX4 receipt-time stamping (timestamp=0), verified
against this installed build's XRCE decoders. Sensor timestamps are not reused
as command timestamps. Position/height/heading resets latch a fault and stop output;
leave Offboard, then restart the publisher to capture the new origin.
Backward mapped timestamps require three advancing valid samples for motion.
The fixed target/heartbeat continue only within the previous trusted sample's
one-second freshness bound; the correction itself never refreshes that bound.
Publisher diagnostic changes are saved to logs/ros2_hover_status.json.

Landing / stop / restart
-----------------------
In the PX4 SITL console: commander land
After landing mode is confirmed, stop the Offboard example with Ctrl+C so it
does not continue requesting hover. Wait for the body to land and disarm.
For an immediate simulation motor cutoff: commander disarm -f
Pausing Isaac freezes simulated time; stopping it closes the bridge.
After Stop/reset, shut down and restart PX4 - Isaac SITL, load the bridge again
while Isaac is stopped, then press Play. Do not reuse PX4 across a time reset.

Configuration and model limits
------------------------------
bridge_config.json contains body paths, rotor positions, ordering, coefficients,
noise and simulator address. WSL's IPv4 address is discovered on every load.
Body convention: forward +X, left +Y, up +Z (FLU); world is ENU.
Motor mapping for NVIDIA's Quadcopter asset:
  PX4 0 = FR = rotor3 = yaw sign -
  PX4 1 = RL = rotor1 = yaw sign -
  PX4 2 = FL = rotor0 = yaw sign +
  PX4 3 = RR = rotor2 = yaw sign +
The bridge reads rotor centres from the composed scene. The starter's control
allocation geometry assumes the stock square asset with arm coordinates
0.10253 metres; update both the config and starter for a different aircraft.

omega = normalized_motor_command * omega_max, with first-order motor lag.
thrust_i = k_f * omega_i^2; reaction_yaw_i = sign_i * k_m * omega_i^2.
Moment arms are included. The summed wrench is applied at chassis COM.
All thrust is cut immediately on disarm or when actuator packets are older
than 0.5 wall-clock seconds. The bridge never sets body velocity or pose.

With k_f/k_m null, coefficients are starting estimates from the total rigid
body mass, hover command 0.5 and yaw moment arm 0.05 m. They are NOT measured
propeller coefficients. No aerodynamic drag, wind, propwash or visual rotor
animation is implemented. This is an initial free-flight/control integration.
Small sensor noise is necessary for PX4 stuck-sensor checks and gyro FIFO
quantization. Sensor coordinates are converted from ENU/FLU to NED/FRD.
